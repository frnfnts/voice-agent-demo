# プロンプト改善観察ログ

実際の面談ログから観察された不自然な振る舞いと、その分析を記録するアーカイブ。
プロンプト本体 (`prompt.txt`) は本ファイルから蒸留された3原則のみを含む。
新しい問題が見つかったらここに追記し、必要に応じて `prompt.txt` に反映する。

**3原則 (蒸留された指針):**
- 原則1: 引用は「情報を整理するため」にだけ使う
- 原則2: 質問は「まだ知らない具体的な事柄」を聞くために組み立てる
- 原則3: 深掘り視点は「target を埋める手段」であり、ローテーション自体が目的ではない

---

## 原則1関連: 引用の不自然さ

### 1-1: 文頭での単語引用
**ログ:** `talk_log/3.log` ほか

**例:**
- 「**異動**、きっかけだったんですね。具体的に…」
- 「**教育**の部分ですか。…」
- 「**長時間労働**、つらかったですね。…」
- 「**多少**、そうだったんですね。…」

**分析:** LLM は「聞いている感」を出すために相手の最後の単語をエコーバックする傾向。人間の面談者は文頭で「呼吸」(受け止め句) を入れる。

**対処:** 文頭は受け止め句で始め、引用は文中・文末に限る (原則1)。

### 1-2: 程度副詞・抽象語の引用
**例:**
- 相手「多少はありました。」→「**多少**、そうだったんですね…」
- 相手「なんか色々重なって。」→「**色々**あったんですね…」

**分析:** 程度副詞・指示語は情報量ゼロ。引用しても会話の前進にならない。

**引用してはいけない語のカテゴリ:**
- 程度副詞: 多少、ちょっと、なんか、たぶん、結構、あまり、まあ
- 指示語・抽象語: それ、そういうこと、いろんなこと、色々、いくつか
- 内容語を含まない返答: 「はい」「特にない」「分かりません」「決まってないです」

### 1-3: 全文復唱・要約
**例:**
- 「ものづくりへの情熱があったのですね。達成感を重視されての入社だったということですね。地元で社会に貢献できる仕事をしたいという思いもあったのですね。」
- 「繁忙期のプレッシャーや、ミスへの圧力が辛かったのですね。その中で適性を考え始めたということですね。」

**分析:** 複数キーワードを順に羅列・要約する応答は、情報の整理ではなく相手の発言の単純な反復。

**対処:** 1ターンの反応部分は最大1文40文字以内。引用は原則1の条件を満たす場合のみ。

### 1-4: 「ご希望しっかり受け止めました」のような営業的フレーズ
**ログ:** `talk_log/6.log`

**分析:** 形式的な「丁寧さ」を演出する定型句で、会話の自然な温度感から外れる。

**対処:** 受け止め句は「なるほど」「そうですね」「そうだったんですね」「分かりました」「承知しました」程度のシンプルな相槌に限定。

## 原則2関連: 質問の不自然さ

### 2-1: 抽象語のみの質問 (「変化を感じましたか?」)
**ログ:** `talk_log/8.log` line 58

**コンテキスト:** Step 3 で「いつ頃から?」→ ユーザー「あんまり覚えてないですね」→ AI 「数か月くらいの中で、何か変化を感じ始めたタイミングはありましたか?」 → ユーザー「変化って何に対する変化ですか?」と困惑。

**分析:** 「変化」「それ」など抽象的な指示語を質問の主語にすると、相手は何を答えればいいか分からない。LLM は視点 (時系列) というメタ指示から逆算するため、具体性が抜け落ちる。

**対処:** 抽象語のみで質問しない。「気持ちの変化」「業務量の変化」「環境の変化」など何の変化かを明示 (原則2)。

### 2-2: 既出情報の再確認質問
**ログ:** `talk_log/8.log` line 65-69

**コンテキスト:** Step 4 でユーザー「半分一人で現場を回す機会が増えて、残業がついた」→ AI 「残業が増えたことで、具体的にどんな影響がありましたか?」

**分析:** 「残業がきつい・つらい」はユーザーが既に表明している情報。それを「影響は?」と聞き直すのは循環的で、新しい情報を取りに行けていない。

**対処:** 残業など問題状況が既出の場合、影響を再度問わない。状況の具体性 (週何時間・期間・原因) を聞く。原則2 (既出情報の再確認禁止) と原則3 (感情既出時の影響視点禁止) の両方に関係。

## 原則3関連: 深掘り視点の選択ミス

### 3-1: 「覚えていない」後の同視点での再質問
**ログ:** `talk_log/8.log` line 49-58

**コンテキスト:** Step 3 で時系列「いつ頃から?」→ ユーザー「覚えていない」→ 再び時系列「変化を感じ始めたタイミングは?」

**分析:** 評価 LLM が「target = 退職を意識し始めた時期」を未取得と認識し、機械的に時系列視点を再選択。しかしユーザーは既に「覚えていない」と表明しており、同じ角度では引き出せない。

**対処:** 直前の視点でユーザーが「分からない・覚えていない」と答えた場合、その視点での再質問は禁止 (原則3)。`edges.py` の STEP_TRANSITION_PROMPT 側でも同じルールを適用。

### 3-2: 感情既出時の影響視点
**ログ:** `talk_log/8.log` line 65-69 (上記 2-2 と同じ)

**対処:** 感情的影響が既出の状況では、影響視点よりも量・頻度・原因を把握できる視点 (具体エピソード・比較・時系列) を優先。`edges.py` の STEP_TRANSITION_PROMPT 側にも同じルールを記載。

### 3-3: 具体エピソード視点の連続使用
**ログ:** `talk_log/3.log`

**例:** 5ターン連続で「具体的に〜」と聞く

**分析:** LLM は「具体的に」が万能だと学習しており、視点をローテーションせず多用する傾向。

**対処:** 具体エピソード視点は連続使用しない。target に合うなら他の視点を優先。

### 3-4: ステップ目的と無関係な深掘り (Step 1 での個人的動機の掘り下げ)
**ログ:** `talk_log/8.log` line 14-24

**コンテキスト:** ユーザー「地元に長く働きたかったのと、ものづくりがやりたかった」→ AI が具体エピソード視点で2ターン連続「どんなものづくりに関わりたかったか」「どのような製品に携わりたかったか」と深掘り。

**分析:** 2層の問題がある。
1. 視点選択ミス: 「地元で働きたい」という動機への最初の掘り下げとして「エピソードは?」は不自然。「なぜ地元が良かったんですか?」（感情・背景視点）の方が自然。
2. ステップ設計の問題（より本質的）: Step 1 の目的は Step 2（ギャップ）のベースライン把握にある。立地・業種選好などの個人的・不変的な動機の詳細は会社側が改善できる要素ではないため、深掘りしても組織改善情報として価値がない。

**対処:**
- Step 1 の purpose を「Step 2 のベースライン把握」に修正
- instruction に「個人的動機（立地・業種選好）が中心の場合は深掘りせず、入社時の職場環境への期待に切り替える」旨を追記
- target 1 を「ざっくり把握で十分。組織改善に繋がらない個人的動機は深掘りしない」に変更
- target 2 を「会社側が変えられる要素（業務内容・教育・チーム・働き方）への期待」に明示

## 取得項目 (target) の設計変更履歴

### Step 4 target の調整 (2026-05-17)
- **旧:** 「複数理由がある場合のそれぞれの内訳」
- **新:** 「その理由の具体的な状況（量・頻度・期間・発生した背景など）」

**理由:** 「残業が決め手」のような単一理由のケースで、深掘りの方向性 (量・期間・原因) が target で示されず、評価 LLM が機械的に影響視点を選んでしまっていた (3-2 の問題)。target を「具体的状況」に変更することで、未取得時に量や頻度を聞く方向に誘導される。
